# Changelog

## Unreleased

- The Windows camera turns on only while an app on the Mac (Zoom, Meet, FaceTime…) uses InputBridge Camera, and turns off a few seconds after; switching to the Mac profile no longer lights it up.
- InputBridge Camera now loads on signed builds: the extension is named after its bundle ID, declares its usage description and pulls frames from Windows over the network instead of through /tmp, which its sandbox does not allow.
- New `InputBridge-macOS.pkg` installer: installs into Applications and opens InputBridge. The DMG is still published for the in-app updater.
- When macOS waits for approval of InputBridge Camera, a setup window opens the right System Settings page with one click.
- Camera sharing is on by default for new Windows installs.
- Controllers show up under Discovered controllers again without Check address: the Windows responder now reads and writes the camelCase discovery messages, and the Mac also checks the paired and manually entered addresses over HTTP every 30 seconds.
- macOS asks once for camera access: without it InputBridge cannot see InputBridge Camera to configure it. InputBridge never turns a camera on itself.
- Release builds are signed with Developer ID, notarized and stapled when the signing secrets are configured.

## 0.2.7

- Windows and Mac profiles now also switch a G915/G913 keyboard between LIGHTSPEED (Windows) and Bluetooth (Mac) using HID++ CHANGE_HOST. The PC switches it to the Mac through its receiver; the Mac switches it back over Bluetooth, including when the Windows profile is chosen on the PC.
- New Keyboard page on Windows (enable, name pattern, detect) and a keyboard option in the Mac's Devices settings.

## 0.2.6

- New InputBridge app icon on Windows (exe, installer, window, tray) and macOS (app icon, menu bar).
- Redesigned Windows controller window: sidebar navigation, card layout, toggle switches and an update banner.
- Redesigned macOS menu bar panel and settings window (sidebar + grouped forms).
- When an update is ready, the tray icon (Windows) and menu bar icon (macOS) show an orange "!" badge; Windows also badges the taskbar button.
- Beta channel: "Receive beta versions" offers GitHub pre-releases (tags like `v0.3.0-beta.1`) in both apps; versions compare by SemVer so betas update to later betas and to the final release.
- Tags with a suffix are published as GitHub pre-releases.

- Windows and macOS apps check GitHub Releases for new versions, download the installer in the background, verify its SHA-256 digest and install it on request (or automatically when enabled).
- Windows installer restarts InputBridge after silent (in-app) updates and no longer duplicates firewall rules on reinstall.

- macOS Z407 discovery scans in parallel with reconnect, keeps the control session after a successful handshake, and no longer blocks monitor switching if the speaker is missing.
- Optional Windows USB camera share publishes 1080p JPEG over the paired local API; a signed macOS Camera Extension appears as InputBridge Camera.

## 0.2.0

- GitHub release workflow and release documentation added.
- Windows controller source hardened for local/private network requests.
- Windows controller serializes profile changes to avoid overlapping monitor commands.
- macOS build moved to a real Xcode application project generated by XcodeGen.
- macOS discovery keeps controller identity stable while its IP changes.
- G915 monitor uses IOBluetooth first and preserves the proven system-profiler fallback.
- Generic setup documentation now avoids any user-specific IP, token or monitor name.
